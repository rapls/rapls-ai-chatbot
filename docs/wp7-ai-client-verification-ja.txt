================================================================================
 Rapls AI Chatbot — WordPress 7.0 AI Client 起動確認チェックリスト
================================================================================
作成日: 2026-05-18
対象: WordPress 7.0 RC4 以降の AI Client / Connectors 統合
関連プロバイダ実装: includes/ai-providers/class-wpai-provider.php

上から順に確認してください。問題が出た時点で止めて、レスポンス本文・ヘッダ
・debug.log を共有していただければ、追跡が容易です。


[A] 環境の前提条件
--------------------------------------------------------------------------------
[ ] WordPress のバージョンが 7.0 RC4 以降
    （wp-admin フッター、または <meta name="generator"> で確認）
[ ] PHP 7.4 以降（wp-admin → ツール → サイトヘルス → 情報 → サーバー）
[ ] Rapls AI Chatbot 1.7.7 以降 が有効
[ ] Connector を提供するプラグイン（例: OpenAI AI Provider）が
    インストール／有効化されている
[ ] サイトヘルスで致命的エラーが出ていない

迅速な確認コマンド（任意）:
    wp option get blogname
    wp eval 'echo function_exists("wp_ai_client_prompt") ? "OK\n" : "MISSING\n";'


[B] Connectors 側の設定
--------------------------------------------------------------------------------
[ ] wp-admin → 設定 → Connectors ページが開く
[ ] OpenAI 用の Connector が登録されている
[ ] API キーが入力済み（マスク表示で残っている）
[ ] Connector のステータスが「有効」「接続済」「Configured」相当
[ ] Connectors のテスト機能（ある場合）で疎通成功


[C] プラグイン側の設定
--------------------------------------------------------------------------------
[ ] Rapls AI Chatbot → 設定 → AI Provider ドロップダウンに
    「WordPress AI Client（Connectors 経由）」が表示される（WP 7.0 のみ）
[ ] 選択して保存後、ページ再読込でも選択状態が維持されている
[ ] wpai-settings セクションに
    「テキスト生成用の Connector が設定されています。」が緑系で表示される
[ ] API キー入力欄が表示されない
    （他プロバイダと異なり、ここでは入力しない）
[ ] モデル欄に「自動（設定 → Connectors で管理）」+
    GPT-5 / GPT-4o / Claude Opus 4.7 / Gemini 2.5 Pro などの curated リスト
    が出る
[ ] 「自動」と任意の個別モデルの両方を選んで保存できる
[ ] 「これは using_model_preference() に渡される優先指定です…」の
    説明文が日本語で表示される


[D] フロント基本動作
--------------------------------------------------------------------------------
[ ] サイト前面でチャットウィジェットが開く
[ ] 「こんにちは」を送信 → 自然な日本語応答が返る
[ ] DevTools → Network → /wp-json/rapls-ai-chatbot/v1/chat が 200 OK
[ ] レスポンスヘッダーに x-raplsaich-debug-reason が含まれていない
    （あれば内容を共有）
[ ] 「この機能は現在利用できません。」「API キーが設定されていません」
    のいずれも出ない
[ ] 1 メッセージあたり 30 秒以内に返ってくる（タイムアウトしない）


[E] モデル選択の挙動
--------------------------------------------------------------------------------
[ ] Auto: 既定モデルで応答が返る
[ ] Connectors で実際に有効になっているモデル（例: gpt-4o-mini）を選択
    → そのモデルで応答
[ ] Connectors に無いモデル
    （例: claude-opus-4-7 を OpenAI のみ接続時に選択）
    → 自動フォールバックで OpenAI のいずれかが応答（エラーにならない）
[ ] マルチターン会話で過去の発言を踏まえた返答が来る
    （system_prompt / 履歴が反映）
[ ] 設定画面の temperature を 0.1 と 1.0 に変えて応答の揺らぎ方が変わる
[ ] max_tokens を 100 に絞ると応答が短くなる


[F] 日本語表示の確認
--------------------------------------------------------------------------------
サイトロケールが ja の状態で:

[ ] AI Provider ドロップダウン:
    「WordPress AI Client（Connectors 経由）」
[ ] モデル欄の Auto 行:
    「自動（設定 → Connectors で管理）」
[ ] wpai-settings セクションの h3:
    「WordPress AI Client」
[ ] 認証情報の行ラベル:
    「認証情報」
[ ] 説明文:
    「wp-admin の 設定 → Connectors を開いて、
     OpenAI／Anthropic／Google のいずれかをプロバイダとして接続してください。」
[ ] Embedding 注意書き:
    「注意：Claude、OpenRouter、WordPress AI Client は埋め込み API を
     提供していません…」
[ ] Connectors 未設定にした状態で送信 →
    「テキスト生成用の AI Connector が設定されていません。…」
    が日本語で返る


[G] エラー／フォールバック確認
--------------------------------------------------------------------------------
[ ] Connector を一時的に無効化 → フロント送信で
    「No AI Connector is configured…」相当のエラー（日本語）が表示される
[ ] 存在しないモデルを wpai_model に手で入れて保存 →
    送信時にフォールバックで応答が返る（500 にならない）
[ ] 空メッセージ送信 → クライアント側バリデーションで弾かれる
[ ] 同一セッションで連続送信 → 429（レート制限）が正しく動く


[H] 既存プロバイダの回帰確認
--------------------------------------------------------------------------------
[ ] AI Provider を OpenAI に戻して保存 →
    既存の openai_api_key で従来どおりチャットが動く
[ ] 同様に Claude / Gemini / OpenRouter へ切り替えても回帰がない
    （各 API キーが入っていれば）
[ ] 設定画面のドロップダウンで provider を切り替えるたび、
    対応する設定セクション（#openai-settings 等）だけ表示される


[I] ログとパフォーマンス
--------------------------------------------------------------------------------
[ ] wp-content/debug.log に RAPLSAICH 系のエラーが新規記録されていない
    （WP_DEBUG_LOG 有効時）
[ ] ブラウザコンソールに JS エラーが出ていない
    （特に [RAPLSAICH] Unmapped error_code: 警告）
[ ] サイトヘルス → 重要な問題: 「重大な問題」が増えていない


[J] 翻訳ファイルが効いているかの最終確認（ピンポイント）
--------------------------------------------------------------------------------
ターミナルで以下を実行 → 翻訳が .mo に焼かれているか即時確認:

    php -r 'require "C:/Users/shake/Local Sites/hash/app/public/wp-includes/pomo/mo.php"; $m=new MO(); $m->import_from_file("C:/Users/shake/Local Sites/hash/app/public/wp-content/plugins/rapls-ai-chatbot/languages/rapls-ai-chatbot-ja.mo"); echo $m->entries["WordPress AI Client (Connectors)"]->translations[0], "\n";'

[ ] 出力が「WordPress AI Client（Connectors 経由）」になる


================================================================================
 詰まったときに即座に欲しい情報
================================================================================
問題があったら、以下を貼っていただけると最短で原因特定できます:

1. HTTP ステータス + レスポンス本文
   （DevTools → Network → /chat）
2. レスポンスヘッダーの x-raplsaich-debug-reason の値
3. 設定画面の AI Provider が wpai で保存されているか
4. WordPress / PHP のバージョン
5. wp-content/debug.log の該当時刻前後の行
